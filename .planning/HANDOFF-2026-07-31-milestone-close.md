## ⚠️ Traps that each cost a wrong verdict — do not relearn these

- **`constitutionFsAuthority.generated.ts` is regenerated by any local `bun run package`, with a
  LOCAL trust-root sha256. NEVER commit it.** `git checkout` it after every build. Committing it
  would be spoofing the trust root.
- **A sealed package cannot be built locally, by design.** `build-mac:arm64` stops at
  `WAYLAND_CAPABILITY_RECEIPTS_DIR is required`. Receipts carry per-capability proof digests bound
  to the commit; manufacturing them is forging attestations. `bun run package` (the vite half) is
  fine.
- **`rtk` summarises `npx tsc`.** Use `rtk proxy npx tsc` when you need raw errors — e.g. for a
  negative control. A "clean" result may be rtk's summary, not tsc's.
- **Always run a negative control.** Six separate times this session a test only proved something
  because it *failed* with the fix reverted. A security test that passes on the vulnerable code is
  worthless.
- **One run per side is not a bisect.** I concluded the Curator change broke `WorkflowDetailModal`;
  three further runs showed 12/12 passing. It is timing-flaky.
- **Suite flake is contention, and I caused some of it** by leaving a second suite running.
  Clean run: **15,945+ passing**. Known flaky: `conversationBridge.tray` (overshoots its 10s budget
  by ~20ms — will flake in CI forever, worth fixing), `recoveryCapture`, `autoUpdate.integration`,
  `WorkflowDetailModal`, `constitutionFsService`, `recoveryCrypto.vector` (Argon2id, CPU-bound).
